- SDK architecture
  - N-native design
    - No dynamic any-typing, no second-class shims
    - All SDKs enforce identical runtime guarantees through native type systems
    - Bootstrap: Rust, TypeScript, Python
    - Adding a language: bindings crate + vector consumer + surface manifest
    - Plugin authorship contract: see: 02-plugin-model.md#Plugin-ownership
    - Two-tier authoring model
      - Tier 1 engine plugins: distributed as precompiled npm/pip native binaries
      - Tier 2 policy plugins: authored in userland code via native async closures
      - Tier 1 vs Tier 2 execution: see: 02-plugin-model.md#Two-tier-execution-architecture
    - Semantic invariant equivalence
      - Uniform hypervisor safety guarantees enforced across runtimes
      - Rust: typestate transitions validate mounted capabilities
      - TypeScript: two-phase deferred context resolves cyclic plugin types
      - Python: builder assembly validates closure scope prior to boot
      - Failure occurs at the earliest lifecycle phase native to each runtime
      - Resource reclamation invariants
        - Rust: Session implements Drop trait to terminate microVM and drop memory
        - TypeScript: try/finally or using block guarantees session.terminate()
        - Python: async with context manager guarantees __aexit__ terminates VM
        - Unhandled errors abort hypervisor immediately to eliminate zombie runs
      - DX iron rules
        - Zero runtime toolchain tax: distributed with precompiled NAPI/PyO3 wheels
        - Consumers never require cargo, zig, or C compilers on target systems
        - Unhandled foreign handler error catches cleanly; guest never hangs
        - Unhandled host exceptions convert to Decision::Deny or hypervisor abort
        - Structured error envelope carries driver, ring, pid, binary, and errno
    - Filter-before-FFI declaration
      - Declarative filters passed to builder during plugin registration
      - Host core evaluates rules natively; non-matching events skip FFI
    - Testkit contract: see: 02-plugin-model.md#Plugin-testkit
    - Rust: borrow-checker verified handle injection, zero-cost Serde
    - TypeScript: generic context accumulation, TypeBox schema guards
    - Python: RAII context managers, Pydantic v2 validation
    - Scoping: all SDKs support ring, binary, and path filters at mount point
    - Topology rule: distinct environments use separate profile factories
    - Parity mechanism: see: 11-operations.md#Multi-language-parity-gate
    - Non-blocking trap verdicts: c.yield(checkpoint_id) and c.abort(code, msg)
    - Shared memory buffers: session.map_shared_region(tag, size_bytes)
    - Portable snapshots: session.export_snapshot() and session.import_snapshot()
    - Custom vsock RPC services: builder.register_vsock_service(port, handler)
    - Extended plugin modules
      - db_proxy, mesh, lock_broker, supply_chain
      - hyper_density, cas_snapshot
      - wire_ingress (connection parking)
  - Params typed views
    - Host-side typed access on HandlerCtx
      - Rust: c.params::<T>() deserializes from validated buffer
      - TypeScript: params typed by .guard() schema
      - Python: params typed by Pydantic BaseModel
    - Zero-allocation validation: operates on zero-copy guest memory
  - Rust SDK
    - see: artifacts/code/rust-handle-injection.rs
    - Typestate builder transitions KelirBuilder<Unset> to KelirBuilder<WithPlugin>
    - Closures requiring plugin capabilities enforce builder typestate bounds
    - Zero-Allocation Validation via Serde
      - #[derive(Deserialize)] enum Action with serde(tag = "action")
      - c.params::<Action>() fails at perimeter before traps execute
    - Scope constraint via MountOptions: rings, binaries, paths
  - TypeScript SDK
    - see: artifacts/code/typescript-accumulation.ts
    - Two-phase builder: .use() registers plugins; .configure() binds hooks
    - Fully unified TContext passes to callbacks, resolving cross-plugin lookups
    - Wraps async TS handlers in ForeignPluginProxy at NAPI boundary
    - Null-object pattern: use(plugin({ enabled: false })) preserves c.pluginKey
    - TypeBox .guard() schema
      - t.Object({ action: t.Literal(...), issueId: t.String() })
      - Falsified spawn actions fail with EINVAL before VM dispatch
  - Python SDK
    - see: artifacts/code/python-raii-pydantic.py
    - async with builder as session
      - __aenter__ boots microVM
      - __aexit__ guarantees session.terminate() on any exception
    - Builder assembly inspects closure freevars against mounted handles
    - Unbound closure references raise KelirConfigurationError before boot
    - Pydantic v2 BaseModel with frozen=True
      - Field(pattern=r"^fix-webhook$")
      - Raises EINVAL before hook evaluation
    - builder, handle = builder.plugin_with_handle(RepoPolicyPlugin())
      - Missing assignment → NameError at import time
    - Mount scoping via kwargs: rings=..., binaries=..., paths=...
  - Full-surface examples
    - see: artifacts/examples/autonomous-swe-agent.rs
    - see: artifacts/examples/autonomous-swe-agent.ts
    - see: artifacts/examples/autonomous-swe-agent.py
    - Position: integration examples, not "the" example
      - Each plugin's own tests/ and examples/ are canonical for that plugin
      - These three demonstrate composition across plugins and rings
    - Each example exercises
      - All five plugins
      - All four VirtIO rings
      - All three epistemic truth tiers
      - All lifecycle superpowers: see: 07-lifecycle.md
    - Not transliterations: each uses language-idiomatic constructs
      - Rust: async-trait, JoinSet, Arc<Mutex<>> handles
      - TypeScript: Promise.all fan-out, generic inference
      - Python: asyncio.gather, async with, Pydantic v2
  - Oracle contract
    - Oracle interface: see: 08-epistemic.md#Oracle
    - Language-specific realization
      - Rust: Arc<dyn Oracle>, threaded through handler closures
      - TypeScript: Oracle object literal, captured by closures
      - Python: subclass kelir.Oracle, methods async
    - Missing method fails at compile / import time in every language
