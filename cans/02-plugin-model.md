- Plugin model
  - Taxonomic coordinate contract
    - Code is sole SSOT: declared programmatically via KelirPlugin trait
    - Manifest artifact is strictly auto-generated for zero-compile indexing
    - Axis 1 (boundary): urn:kelir:<subsystem>:<target>[:<subtarget>]
    - Axis 2 (rings): set of attached VirtIO device channels
    - Axis 3 (tier): Native (Rust in-process) | Foreign (host FFI)
    - Axis 4 (telemetry role): Observer | Gate | Mutator | Proxy
    - First-class catalog default: tier is Native unless stated
    - Mutation scope manifest: mutators declare target paths, ports, or envs
    - Overlapping mutation scopes between plugins fail validation at boot
    - Coordinates enforce compile-time ordering gates and dispatch layout
  - Universal taxonomy subsystems
    - net: L2 TAP frames, L4 streams, L7 protocol termination
    - fs: FUSE VFS operations and virtio-blk block images
    - io: PTY streams and multiplexed console channels
    - sys: traps, process trees, clock, faults, audit receipts
    - ipc: vsock multiplexing and shared-memory mapping
  - Two-tier execution architecture
    - Native tier
      - Compiled native Rust plugins in crates/kelir-plugins
      - Synchronous fast-path filters execute on VirtIO rings at <1µs
      - Returns SyncVerdict::Allow or yields to host via SyncVerdict::YieldToHost
      - Direct memory execution on 4 VirtIO rings at sub-12µs latency
      - High-frequency mutation: raw PTY ANSI, FUSE CoW, TAP L2 frames
    - Foreign tier
      - Userland host plugins authored in TypeScript, Python, or Rust
      - Executes in host runtime event loop via ForeignPluginProxy
      - Steers agent workflows, prompt rules, branch gates, and masks
  - Foreign plugin proxy
    - Bridges language runtimes to KelirPlugin trait via NAPI/PyO3
    - AOT hook fusion compiles chained host hooks into a single flat closure
    - Exactly one FFI trampoline crossing per ring event regardless of hook count
    - Marshals ring events across threadsafe boundaries on match
    - Non-blocking trap returns: Allow, Deny, Rewrite, Yield, Abort
  - Composite plugin hierarchy
    - see: artifacts/code/plugin-trait.rs
    - Assembly-time tree flattens into contiguous C-speed dispatch array
    - Invariant: nested depth incurs zero runtime call-stack overhead
    - Deduplication merges identical name() nodes; deepest config wins
    - AOT hook fusion collapses nested closures into single FFI trampoline
  - KelirPlugin trait
    - see: artifacts/code/plugin-trait.rs
    - Trait surface and hook families: see: artifacts/code/plugin-trait.rs
    - Error variants
      - Ok(()) = allow; kernel proceeds
      - Err(Reject { errno, reason }) = deny with named errno, pre-write
      - Err(Halt(msg)) = deny and halt pipeline for human review
      - Err(Io(_)) = internal failure, surfaced to runtime
    - Shape of the surface
      - Every hook is `async` and returns `Result<_, PluginError>`; a hook
        cannot block the dispatch array
      - Hooks map strictly to VirtIO transport events and hypervisor transitions
      - Every ring has both an observation and a mutation point; the trait
        never exposes a ring for observation only
      - The surface is closed per ring; adding a hook is a spec change, not
        a plugin concern
    - Why the surface is this size
      - A hook exists only if a ring delivers the event it consumes
      - A hook that a plugin does not implement defaults to `Ok(())`;
        "opt-in" is the trait's typing, not a runtime branch
    - Hook context restriction
      - Every hook receives HandlerCtx or a restricted lifecycle context
      - No hook receives &mut Box<dyn VmmDriver> or &Session
      - LifecycleCtx exposes: set_watchdog, adjust_balloon, register_veto
      - Lifecycle commit: on_pre_commit, on_post_commit, on_host_preempt
    - VfsInodeAttr carries full mode, uid, gid, size, content
      - Populated verbatim into FUSE LOOKUP replies
      - Synthetic FUSE inodes honor mode: 0o400 exactly, no permission fallback
    - Plane semantics
      - Wire plane fully bidirectional: outbound and inbound mutation points
      - Storage plane fully attributed: on_vfs_write carries PID and HandlerCtx
      - Control plane messages hook-observable; nothing bypasses the graph
    - Hook return semantics
      - on_vfs_write: see: 05-storage-plane.md#Write-gating (storage owns it)
      - on_vfs_lookup → Ok(None) = fall through; Ok(Some(attr)) = serve
      - on_net_outbound / on_net_inbound → see: artifacts/code/plugin-trait.rs
  - Declarative error mapping
    - Host exceptions map directly to POSIX errnos via builder error registry
    - Unmapped exceptions convert cleanly to Decision::Deny or hypervisor abort
    - Preserves guest POSIX semantics without manual try-catch in hook bodies
  - Declarative plugin macros
    - Plugins expose declarative DSL attributes expanding at assembly time
    - Macros inject MountScope filters, BPF allowlists, and fused hooks
    - Eliminates procedural condition checks inside userland hook bodies
  - Static dispatch
    - Plugins compiled into flat contiguous dispatch array at boot
    - Core verifies plugin dependency DAG: cycles and missing deps halt boot
    - Evaluated in priority() order; ties broken by declaration order
    - Monotonic permission lattice: Allow -> Rewrite -> Deny -> Abort
    - Restrictive monotonicity: downstream hooks cannot widen upstream denial
    - Fail-closed mutation collisions: overlapping writes raise EAmbiguousMutation
    - Deduplication: identical name() instances merge; deepest config wins
    - Dispatch pruning: no-op hooks completely omitted from C-dispatch table
    - Zero-cost null objects: disabled plugins retain types, cost zero in core
    - fork_state() deep-clones state instances during session.vm.fork()
    - Native zero-WASM isolation: compile-time linear capability tokens
    - Immutable &[u8] slice views prevent cross-plugin heap tampering
    - Hardware MPK page keys isolate per-plugin memory domains in-process
    - requires() validated at boot; missing dep aborts boot with EConfig
    - Lock-free dispatch swap via ArcSwap on the host event bus (internal)
    - ArcSwap serves atomic dispatch swapping during snapshot hydration only
    - Not a public runtime API; session configuration is frozen after boot
    - First Deny or Rewrite halts pipeline, dispatches over AF_VSOCK
    - Sub-12 microsecond hook execution
    - on_trap_deny is builder-level, not a plugin hook
      - Deny-observation composition is a user concern
  - Mount scoping
    - Mount-level filters restrict blast radius before dispatch evaluation
    - VirtIO ring mask: unselected rings bypass plugin completely
    - Multi-port console partition: routes hvc0 to pty and hvc1 to mcp
    - Binary filter: in-kernel BPF drops traps for unlisted paths
    - Path filter: FUSE layer bypasses VFS hooks outside declared subtrees
    - Network filter: TAP dispatcher bypasses net hooks outside declared CIDR/port rules
    - Scope cascade: see: artifacts/code/plugin-trait.rs
    - Invariant: child effective scope is boolean intersection of ancestor scopes
  - Filter-before-FFI gate
    - Unmonitored guest operations bypass host language runtimes entirely
    - Host core checks MountScope in native memory before crossing FFI
    - Evaluates native compiled schema validators alongside MountScope
    - Zero FFI allocation on non-matching or invalid events
    - FFI trampoline executes only when ring event satisfies scope match
    - Protects guest toolchain execution speed (cargo build, npm install)
    - TAP dispatcher application: see: 06-wire-plane.md#Raw-packet-interception-points
  - FFI buffer lifecycle
    - Pinned memory slices exposed via streaming chunked iterators
    - Prevents use-after-free while host runtimes resolve handlers
    - Payloads exceeding 64KB ceiling trigger BufferCeilingExceeded
    - Handlers must reject uninspected payloads or delegate to Rust plugins
  - Core context keys
    - Handler-visible keys; each key's definition lives at its owning plane
    - Invariant: core runtime carries zero hardcoded plugin context keys
    - Host context carries typed extension map for plugin-contributed data
    - Language SDKs accumulate context keys via phantom types or plugins
    - Core-provided (always present)
      - c.trap, c.env, c.vm, c.step, c.receipt()
    - Context key lifecycle
      - Static decoration via decorate(): states bound once at VM boot
      - Lazy derivation via derive(): computes telemetry only on handler access
    - Plugin-provided (accumulated strictly by SDK builder at compile/type time)
      - Plugin states map to typed properties on the accumulated context
      - Unmounted plugin key dereference fails compile or import time
    - User-provided via plugin registration
      - c.<key> from .decorate() or instantiated plugin state

  - Plugin ownership
    - Dependency rules
      - Zero inter-plugin dependencies: no plugin imports another plugin crate
      - Depends on kelir-interface (traits, context types) only
      - Data-flow dependencies expressed via typed bus schemas, not code
      - Inter-plugin coordination passes linear tokens via hypervisor bus
      - Cryptographic Merkle handoff tracks every in-flight mutation per hook
      - Depends on plugin-testkit as dev-dependency
      - Never depends on crates/kelir facade
      - Cross-plugin coordination occurs via core traits or userland closures
    - Decoupling test
      - Remove the plugin → remaining plugins build and test green
      - A failing plugin's tests are attributable to that plugin alone
      - Executed per plugin by plugin-isolation; see: 11-operations.md#Decoupling-proof
      - Scope: excludes facade (re-exports every plugin), adapter binaries
        (one plugin each), and kelir-integration (dev-depends on all)
      - Dev-dep edge and facade edge: gated by plugin-audit
      - Audit gate detail: see: 11-operations.md#Per-plugin-CI
    - External plugins: same contract; no adaptation
  - Plugin testkit
    - Crate layout: see: 11-operations.md#Project-structure
    - Boundary contract
      - Depends on kelir-interface only; never on a plugin or the facade crate
      - Every plugin depends on it as a dev-dependency
      - Not runtime: shipping it in the runtime crate graph is a defect
    - Purpose: a plugin's tests run without a hypervisor
    - Emits language-agnostic test vectors
      - vectors.json derived from Rust fixtures
  - Auto-generated manifest contract
    - Tooling extracts metadata directly from code AST and taxonomy trait
    - Manual manifest authoring is banned to eliminate dual-source drift
    - Validates 4-axis coordinates, acyclic requires, and disjoint scopes
    - Missing or invalid taxonomy coordinates reject compilation at boot
