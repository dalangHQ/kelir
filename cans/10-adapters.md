- Adapters
  - Ingestion matrix
    - see: artifacts/diagrams/ingestion-adapters.txt
    - Adapter set and ecosystem binding: see: artifacts/diagrams/ingestion-adapters.txt
    - Two shapes, one rule
      - Contract-bound binary + plugin: MCP, containerd shim v2, OpenShell
      - Thin SDK wrapper: E2B (no plugin, no binary) — see: #E2B-compatibility
    - Rule: the plugin owns translation and policy; the binary owns the wire
    - Process vs plugin boundary
      - Shim process owns wire; urn:kelir:fs:block:oci plugin owns policy
      - Server process owns stdio wire; urn:kelir:io:channel:mcp plugin owns policy
      - Driver process owns gRPC wire; urn:kelir:sys:proc:lifecycle plugin owns policy
      - SDK wrapper only: no process, no plugin, no URN
    - Tri-native SDKs are the fourth ingestion family; see: 03-sdk-architecture.md
    - Ingestion tiering and licensing
      - Community adapters: mcp-server (stdio wire), e2b-compat (thin client SDK)
      - Commercial adapters: containerd-shim-v2 (K8s), openshell-grpc (NVIDIA CDI)
      - Commercial adapter SSOT: see: kelir-cloud://cans/01-fleet-orchestration.md
  - MCP adapter
    - Architecture (mcp): see: artifacts/diagrams/ingestion-adapters.txt
    - Server binary crate: kelir-adapters/mcp-server
    - Server plugin: see: plugins/mcp.md
    - Binding maps to Session execution with flat mcp plugin config
    - MCP boundary: see: #Process-vs-plugin-boundary
  - Containerd shim v2
    - Architecture (containerd): see: artifacts/diagrams/ingestion-adapters.txt
    - Shim binary crate: kelir-adapters/containerd-shim
    - Pod isolation
      - Each Pod runs in isolated hardware microVM
      - Not a Linux cgroup/namespace envelope
    - PVC storage
      - PersistentVolumeClaims mount as virtio-fs endpoints
      - UID/GID mapping applied in-guest
    - Shim plugin: see: kelir-cloud://cans/plugins/oci-translator.md
    - Shim maps to Session execution with flat oci-translator config
    - Containerd boundary: see: #Process-vs-plugin-boundary
  - OpenShell gRPC driver
    - Architecture (openshell): see: artifacts/diagrams/ingestion-adapters.txt
    - Driver binary crate: kelir-adapters/openshell-grpc
    - Coordinator plugin file: see: kelir-cloud://cans/plugins/openshell-coordinator.md
    - Driver maps to Session execution with flat openshell-coordinator config
    - OpenShell boundary: see: #Process-vs-plugin-boundary
  - E2B compatibility
    - TypeScript: @kelir/e2b-compat
    - Python: kelir.compat.e2b
    - Preserves existing E2B Sandbox method signatures
      - Sandbox.create, sandbox.commands.run, sandbox.files, sandbox.pty, sandbox.kill
    - Replaces remote cloud VM roundtrips with sub-60ms local hardware execution
    - Drop-in: frameworks built against E2B SDK require no code change
    - Implementation: thin SDK wrapper
      - No plugin: Sandbox methods map directly to Session methods
      - No binary: consumes the same in-process SDK as first-class consumers
      - E2B boundary: see: #Process-vs-plugin-boundary
