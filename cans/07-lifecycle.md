- Lifecycle
  - Hypervisor primitives
    - Centralized Hypervisor Lifecycle State Machine:
      - States: Initializing, Running, Suspended(SuspendReason), Terminated
      - SuspendReason: External(u32) | ResourcePressure
      - Eliminates independent suspend implementations outside core
      - Working-set swap: see: #Suspend-and-resume
      - Cycle-exact resume triggered via vsock Channel 0 patch or TAP frame arrival
    - Set-level invariant: every item is a hypervisor primitive, not a
      guest-side simulation. Nothing in this set is achievable without driver
      cooperation.
    - Per-primitive exercise map
      - fork, rollback: autonomous-swe-agent.{rs,ts,py}
      - suspend, resume, skew_clock: autonomous-swe-agent.{rs,ts,py}
      - watchdog, breakGlass, forward_port: autonomous-swe-agent.{rs,ts,py}
      - map_shared_region: multi-vm-swarm.rs
      - register_veto: multi-vm-swarm.rs
      - export_snapshot, import_snapshot: db-backed-runtime.py
      - adjust_balloon: serverless-webhook.ts
    - Exercise invariant
      - Every primitive mounts end-to-end in one example file
      - An unexercised primitive fails --lifecycle-coverage
      - Lifecycle-coverage gate: see: 11-operations.md#Coverage-gates
      - Veto-coverage: every VetoEvent registered at least once
        - Fork, Suspend, ClockSkew, Checkpoint, Rollback, Resume, Terminate
        - An unregistered VetoEvent fails --veto-coverage
        - Veto-coverage gate: see: 11-operations.md#Coverage-gates
        - Veto classes: see: #Lifecycle-vetoes
      - Watchdog-coverage: Suppress and Mitigate returned at least once
        - ExecuteDefault alone does not satisfy watchdog-coverage
        - An unreturned verdict fails --watchdog-coverage
        - Watchdog-coverage gate: see: 11-operations.md#Coverage-gates
        - Verdicts: see: #Watchdog
    - Shared memory mapping: see: 01-architecture.md#Shared-memory-channel
    - Portable snapshots: see: #Portable-snapshot-bundles
    - Two-phase commit protocol: see: #Two-phase-commit
    - Preemption window: see: #Host-crash-reaper
    - Every item exposes one lifecycle point via LifecycleCtx
      - Typestate boundary: fork, suspend, rollback, skew_clock exist
        exclusively on Session, never on KelirBuilder
      - Split by state-preservation, not by privilege: see: #Lifecycle-vetoes
    - Ownership attribution: see: 02-plugin-model.md#First-class-plugins
    - Hardware session attestation:
      - Core injects ephemeral one-time session token over paravirtual config
      - Workloads verify token over vsock Channel 0 before starting harnesses
      - Bare-metal executions lack the paravirtual token and abort immediately
      - Protects developers running harness scripts natively by mistake
  - CoW fork
    - Driver primitive: fork returns Box<dyn VmmDriver>
      (timing: see: artifacts/code/vmm-driver-trait.rs)
    - KVM path: userfaultfd + KVM memory cloning
    - HVF path: Stage-2 translation table write protection (hv_vm_protect)
    - Host runtime calls fork_state() to isolate plugin states per branch
    - Children share warm parent memory
      - Warmed compilers, loaded dependencies, in-process caches
    - Host RAM dirtied only on child write
    - Session hydration
      - Driver fork yields raw Box<dyn VmmDriver>
      - Runtime re-hydrates complete Session around it
      - Rebinds 4-ring dispatch table, virtio channels, plugin graph
      - session.vm.fork() returns full Session
      - spawn() and every other session API directly callable on child
    - Child handoff scope: TBD
    - Typical use: parallel agent exploration (5+ candidate strategies)
    - Policy dry-run CoW probing
      - Clones parent VM to evaluate untrusted candidate commands
      - Policy denial in probe child aborts branch in <1ms with zero parent impact
      - Probe execution asserts hardware receipts before parent commits diff
    - Veto: Fork (hard)
      - Callback false → ESessionVeto; no child VM
  - Rollback
    - Driver primitive: rollback reverts
      (timing: see: artifacts/code/vmm-driver-trait.rs)
    - Reverts guest memory, registers, and tmpfs overlay diffs
    - HVF path: resets Stage-2 translation table roots to snapshot base
    - Used by HandlerCtx post-exec on post-condition violation
    - Does not touch host SSD or Merkle WAL
    - Veto: Rollback (observation)
      - Cannot be vetoed; rollback is the recovery action
      - Use for ledger/trace of recovery events
  - Suspend and resume
    - suspend
      - Reason: SuspendReason::External or ResourcePressure
      - Freezes vCPU registers
      - Page-dump engine: lz4_flex compression over io_uring direct I/O
      - Flushes compressed pages to local NVMe
      - Host RSS drops to 0 MB; see: artifacts/code/vmm-driver-trait.rs (suspend)
    - resume
      - Restores registers and memory
      - Resumes at exact cycle boundary
    - Snapshot contents: TBD
    - Veto: Suspend (hard), Resume (observation)
      - Suspend false → ESessionVeto; host RAM not flushed
      - Resume fires before primitive; return value ignored
      - Note: on_vm_ready does not re-fire on resume
    - Typical use: waiting for human approval with zero host CPU cost
    - Mobile and SBC use: full RSS deallocation under Android LMK memory pressure
    - Flash preservation: guest tmpfs writes stay in RAM; zero random SD card writes
    - External suspension
      - Triggered by SuspendReason::External(u32) awaiting out-of-band release
      - Managed via plugin-checkpoint: see: plugins/checkpoint.md
      - Resume executes cycle-exact upon external release signal
  - Portable snapshot bundles
    - Content-addressed snapshot sync
    - Streamed archive packaging vmm_state.json, ram.zst, and upperdir diff
    - session.export_snapshot() yields portable binary stream (.kelir-snap)
    - session.import_snapshot() hydrates session across identical hosts
    - Decouples long-running human approval pauses from host machine uptime
  - Clock skew
    - KVM path: KVM_SET_CLOCK and kvm_clock MSRs
    - HVF path: ARM64 CNTVOFF_EL2 (Virtual Timer Offset Register)
    - Guest CNTVCT_EL0 reads jump forward instantly
    - Paravirtual clock updates route via pvclock structure without unpinning TSC
    - Guest boots with pinned clocksource: clocksource=kvm-clock tsc=reliable nohpet
    - Typical use: JWT expiry, cron cycles, certificate renewals
    - Synthetic virtual clocksource mode
      - Guest clock decouples from host TSC; host advances KVM_SET_CLOCK on
        retired-instruction PMU windows (host vCPU timer ticks), not per
        syscall trap
      - Intercepts timer reads on host without custom guest kernel modules
      - Guarantees cycle-exact deterministic replay across repeated runs
    - Veto: ClockSkew (hard)
      - Callback false → ESessionVeto; guest clock unchanged
  - Lid sleep/wake clock snapping
    - Problem: guest clock stalls on lid close
      - Laptop lid close pauses guest monotonic time
      - Host wall-clock advances; guest time does not
      - TLS handshakes fail on wake due to clock mismatch
    - Solution
      - Listen to host power events: IOPMrootDomain (macOS), systemd-logind (Linux)
      - Dispatch immediate hardware clock resync over AF_VSOCK
      - Guest time snaps to host wall-clock in 0ms
  - Host crash reaper
    - Problem: host crash orphans guest vCPUs
      - Host Node.js / Python process killed abruptly (kill -9, OOM, segfault)
      - Hypervisor children must not survive as orphaned CPU spinners
    - Dual-path by design
      - Linux: prctl(PR_SET_PDEATHSIG, SIGKILL)
        - Applied to every hypervisor backend thread
        - Kernel terminates backend and unmaps memory immediately
        - No polling involved
      - macOS: kqueue(EVFILT_PROC, NOTE_EXIT) watcher on host PID
        - Second channel: parent-monitoring heartbeat pipe
        - On host exit or pipe close: SIGKILL to backend process group
        - Reclaims VM memory mappings
    - Graceful host preemption window
      - In-process Tokio handler catches host SIGTERM; delays SIGKILL
      - Waits preemption_grace_ms; dispatches on_host_preempt() hook
      - Android LMK hook: executes session.suspend() before OS termination
      - Prevents session state corruption during mobile app backgrounding
    - Platform coverage: TBD
  - Two-phase commit
    - MicroVM and host database state synchronization protocol
    - Coordinated via plugin-transaction: see: plugins/transaction.md
    - on_pre_commit pauses vCPUs and flushes in-flight VFS write buffers
    - Staging subtree prepared atomically in host workspace
    - on_post_commit(true) executes atomic directory swap into workspace
    - on_post_commit(false) unlinks staging directory and purges tmpfs diffs
    - Prevents desynchronization between host DB and guest workspace
    - Demonstration target: see: artifacts/examples/db-backed-runtime.py
  - Docker-in-kelir
    - Constraint: Apple Silicon HVF offers no nested VMX/SVM
    - Invariant: OCI containers run without a nested hypervisor and without
      a host daemon
    - Mechanism: rootless Podman + crun inside the read-only EROFS rootfs;
      ephemeral state on tmpfs so the rootfs stays immutable
    - Container contract: TBD
  - Break-glass
    - Supervisor freezes guest agent task group via cgroup freezer prior to attach
    - In-flight PTY buffer drained before exposing raw console master
    - Developer attaches interactive TTY to the interactive console master port
    - Subshell exit clears screen, refreshes window size, and unfreezes agent group
    - Spelling: `breakGlass()` (TS), `break_glass()` (Rust, Py);
      `session.break-glass()` never exists
  - Wire port forwarding: see: plugins/wire.md#Port-forwarding
  - Zombie reaping
    - Shim runs as guest PID 1
    - waitpid(-1, WNOHANG) pass integrated into async event loop
    - Foreground shell exit → orphaned daemons adopted and reaped
    - Prevents defunct <zombie> processes exhausting PID table
  - Lifecycle vetoes
    - Registration
      - LifecycleCtx.register_veto(event, Box<dyn Fn() -> bool + Send + Sync>)
      - Hard vetoes register in on_vm_init using LifecycleCtx.register_veto
      - Pre-boot registration also allowed: builder lifecycle_mut().register_veto
        - Before seal/boot; validated at boot; same VetoEvent, same firing point
      - All veto registrations validated at boot
      - Callbacks fire in DAG order across all plugins
    - Two classes
      - Hard veto: Fork, Suspend, ClockSkew
        - Any false return aborts the action with ESessionVeto
        - Use for policy gates (e.g. "no fork until fixtures ready")
      - Observation only: Checkpoint, Rollback, Resume, Terminate
        - Callback fires; return value logged and ignored
        - Use for ledger / trace / metrics
    - Class is determined by state-preservation, not by event name
      - A state-preserving action cannot be vetoed: aborting it would leave
        no recovery path
      - A state-mutating action (Fork, Suspend, ClockSkew) is vetoable
      - Terminate is observation-only because flush belongs to on_vm_shutdown
    - VetoEvent is the uniform registration type for both classes
    - Firing point
      - Before the corresponding hypervisor primitive executes
      - Session-level actions also route through this point
  - Watchdog
    - see: artifacts/code/vmm-driver-trait.rs (WatchdogAction)
    - Armed via LifecycleCtx.set_watchdog
      - Typically called from on_vm_init by a policy plugin
      - WatchdogAction: Reboot | Terminate
    - Heartbeat
      - Shim emits GuestToHost::Heartbeat at driver-configured cadence
      - on_heartbeat fires per receipt; observation only
    - Firing
      - Driver fires on_watchdog(&WatchdogEvent) when heartbeat expires
      - Hook returns WatchdogVerdict (ExecuteDefault | Suppress | Mitigate)
      - ExecuteDefault triggers configured WatchdogAction (Reboot | Terminate)
      - Mitigate delegates recovery to host policy handler
      - WatchdogAction::Terminate synthesizes WatchdogDiagnostic from host
      - Carries fired_at_ns, last_heartbeat_ms, and last active PID
      - Evaluates completely host-side without guest kernel cooperation
      - This is the extension point for custom actions
        - A plugin may do work in on_watchdog then return Err(Halt)
        - WatchdogAction stays closed (Reboot | Terminate)
