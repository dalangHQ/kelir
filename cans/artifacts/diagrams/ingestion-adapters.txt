│ 1. TRI-NATIVE FIRST-CLASS SDKs:                                             │
│    - Rust: Direct in-process crate linkage (`kelir = "3.0"`)                │

│ 2. MODEL CONTEXT PROTOCOL (MCP):                                            │
│    - In-process `plugin-mcp` connects Claude Desktop/Cursor to VirtIO rings.│
│    - Mediates hardware-isolated execution without exposing host boundaries. │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. CONTAINERD SHIM V2 (Kubernetes Bare-Metal Execution):                    │
│    - Commercial adapter — full diagram in kelir-cloud (private repo).       │
│    - See kelir-cloud ingestion-adapters-commercial diagram.                 │
│    - Image→EROFS translation is kelir-pack (core primitive), NOT the        │
│      commercial plugin: kelir-pack streams tar/OCI blob → EROFS chunks      │
│      into cas/blobs/blake3_<hash>. oci-translator owns containerd-shim      │
│      boundary policy only.                                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. OPENSHELL COMPUTE DRIVER (NVIDIA AI Infrastructure):                     │
│    - Commercial adapter — full diagram in kelir-cloud (private repo).       │
│    - See kelir-cloud ingestion-adapters-commercial diagram.                 │
├─────────────────────────────────────────────────────────────────────────────┤
│ 5. SANDBOX ENGINE COMPATIBILITY (E2B Drop-In):                              │
│    - `@kelir/e2b-compat` (TS) and `kelir.compat.e2b` (Python).              │
│    - Replicates the `Sandbox` interface with local hardware boots.          │
└─────────────────────────────────────────────────────────────────────────────┘
Boundary rule: the process owns the wire; kelir-pack owns image→EROFS
translation; the plugin owns policy only.
Plugins: containerd kelir-pack (translation) + oci-translator (policy); MCP plugin-mcp;
OpenShell plugin-profile; E2B: no plugin.
